# Evaluation

This file has two parts. The **metrics block** is regenerated automatically by
`python evaluate.py` from the latest run (so the numbers always match the code). The
**analysis** below it is written by hand from what I observed while building and testing.

Ground truth lives in `sample_submissions/dataset_manifest.json` (14 files: 6 PDF, 5 DOCX,
3 MP4). Built-in relationships: one exact copy pair, one paraphrase pair, one cross-modal pair
(MP4 reads page 2 of a PDF), one web copy, one LLM-written essay, five documents sharing a
~150-word case prompt, one zero-byte PDF and one MP4 with no audio track.

**Which backend produced these numbers:** the block header states the embedding model and
ASR engine. The development sandbox had no access to Hugging Face, so the committed run used
the offline fallbacks (TF-IDF embeddings, PocketSphinx ASR). On a normal machine
`./run_all.sh` uses all-MiniLM-L6-v2 and Whisper and rewrites this block.

## Scenario 2: why exact-string metrics fail on paraphrase

Lexical similarity between the three paraphrased paragraph pairs (`sub_04` vs `sub_05`):

| Paragraph | Trigram Jaccard | Char ratio (Levenshtein-like) | TF-IDF cosine |
|---|---|---|---|
| Range anxiety | 0.000 | 0.152 | 0.260 |
| Battery swapping | 0.012 | 0.417 | 0.147 |
| Subsidy shift | 0.013 | 0.483 | 0.216 |

Exact-match tools score these pairs near zero, and so does the lexical TF-IDF fallback. That
is exactly why the primary backend is a sentence embedding model. MiniLM cosines for this
pair appear in the metrics block (Scenario 2 row) after a run with `sentence-transformers`
installed. Each match in the reports also carries a `match_type` label (verbatim /
near-verbatim / semantic paraphrase) worked out from the Jaccard value, so reviewers can see
*why* something was flagged.

## Failure analysis

### 1. Paraphrase missed in offline mode (false negative)
* **What happened:** with the TF-IDF fallback, `sub_05_ev_paraphrase.docx` got 0% peer
  similarity. Its best chunk cosine against `sub_04` (about 0.15 to 0.26) is far below the 0.45
  TF-IDF threshold. Synonym swaps ("motorists" for "drivers", "sticker price" for "purchase
  price") leave almost no shared n-grams.
* **Root cause:** lexical vectors cannot capture meaning. This is the expected weakness that
  Scenario 2 is designed to expose.
* **Fix:** use the neural backend (the default whenever the model can load). Beyond that, a
  two-stage design: MiniLM bi-encoder recall at a looser threshold (around 0.70), then a
  cross-encoder (`cross-encoder/stsb-roberta-base` or a paraphrase-mining model) to re-score
  only the candidates. That keeps throughput high and sharpens precision near the boundary.
  The system should also refuse to run "silently degraded": the run header and every report
  already record which backend was used.

### 2. ASR errors nearly broke the cross-modal match (fragile true positive)
* **What happened:** PocketSphinx transcribed "rural health" as "oral health", "phase change"
  as "his change", "cold" as "code" and "spoilage" as "for elite". The cross-modal chunk still
  matched page 2 of `sub_06` with cosine **0.474**, only just above the 0.45 threshold. When I
  tried smaller video chunks (30 and 45 words) to get tighter timestamps, the match **dropped
  below threshold and was lost**: shorter, noisy transcript chunks compared against a longer
  clean PDF chunk score lower.
* **Root cause:** a combination of ASR word error rate and chunk-length asymmetry between
  modalities.
* **Fix:** (a) use Whisper (the default when it is installed; it is far more robust,
  including on accented speech); (b) keep chunk sizes symmetric across modalities and get
  precision from the **sentence-alignment step** instead, which already pinpoints
  `00:00:09-00:00:14` ⇄ p. 2 inside the larger chunk; (c) for noisy transcripts, add
  character n-gram or phonetic (Double Metaphone) matching as a second signal; (d) at scale,
  calibrate thresholds per modality pair (video→pdf separately from pdf→pdf).

### 3. The original author is flagged as HIGH too (ambiguous result)
* **What happened:** `sub_01_original_a.pdf` (the original) and `sub_02_exact_copy_of_01.docx`
  (the copy) both get HIGH risk at about 97%. Likewise `sub_06_cold_chain.pdf` is HIGH because
  the video copied it. The metric is symmetric, so it cannot say who copied whom.
* **Fix:** the report already says this in plain words. In production, I would add
  submission timestamps and team metadata, label the earlier submission as "likely source",
  and route both to a reviewer instead of penalising automatically. The ground-truth scoring is
  at the *pair* level for this reason.

### 4. Template text merged with a title (bug found and fixed)
* **What happened:** in the first version, PDF text blocks were joined before sentence
  splitting. The title "GreenCart Supply Chain - Team Zeta" fused with the first prompt
  sentence, so that sentence no longer matched across the 5 documents. The boilerplate
  detector missed it, and all template documents showed about 6 to 11% spurious peer
  similarity with each other.
* **Fix applied:** split sentences per PDF text block. Spurious template overlap dropped to
  0%. Remaining risk: the detector needs a passage to appear in at least 3 submissions. If
  only 2 teams paste the same prompt, it would be counted as copying. Production fix: let
  organisers upload the official prompt into a `templates/` index that is always discounted,
  and use a corpus-fraction rule (for example, more than 2% of submissions) at scale.

### 5. AI detector limits (known risk, not observed as an error here)
* The stylometric heuristic flags the LLM essay at about 99.7% and every human document below
  about 20%. But its strongest signals (discourse markers, few concrete numbers) are
  **style**, not provenance. A human who writes generic prose full of "furthermore" would be a
  false positive. An LLM prompted to "include specific figures and vary sentence length"
  would be a false negative. On ASR transcripts, the lack of punctuation breaks the
  burstiness feature, so video scores are labelled low confidence. There is only one AI
  positive in the set, so precision and recall of 1.0 is a smoke test, not evidence.
* **Fix:** combine with a model-based score (`--ai_detector roberta`, or GPT-2 perplexity),
  calibrate on a labelled set of a few hundred documents, and never use it as a sole basis for
  a penalty. The report wording says this explicitly.

## Trade-off analysis

**Embedding model: all-MiniLM-L6-v2** (384-d, 22M parameters, about 90 MB). It runs at
hundreds of sentences per second on a laptop CPU and is trained on paraphrase and NLI pairs,
which suits this task. Larger models (`all-mpnet-base-v2`, 768-d, `bge-base`, `e5-base`) give
a few points better STS accuracy at about 5x the compute and 2x the index memory. For
10k submissions × ~50 chunks = 500k vectors, MiniLM needs about 0.77 GB in float32 (about 0.2
GB with PQ compression) versus about 1.5 GB for mpnet. My choice: MiniLM for recall, plus a
cross-encoder only on candidate pairs if precision matters more. The TF-IDF fallback costs
nothing and handles verbatim and near-verbatim copies well (exact copy, web copy and the
noisy cross-modal case all pass), but it cannot do paraphrase.

**Vector index: FAISS `IndexFlatIP`** (exact inner product on normalised vectors = cosine). At
prototype scale (about 100 chunks), exact search is instant, and approximation would only add
recall error to the evaluation. At 500k vectors a flat search is still about 0.2 GFLOP per
query (fine in batch), but all-pairs comparison becomes 2.5×10¹¹ dot products. That is where
HNSW (or IVF-PQ on GPU) takes over; see the README scaling section.

**ASR: Whisper-base** by default (74M parameters, about 1x real-time on CPU, good on accents).
`tiny` is about 3x faster with noticeably more errors, which, as failure 2 shows, directly
affects cross-modal recall. PocketSphinx is the zero-download fallback and is clearly worse.

**Chunk size: 60 words with 1-sentence overlap** instead of the suggested 200 to 400 tokens.
The sample documents are 150 to 400 words. A 300-token chunk would be the whole document,
which turns plagiarism localisation into document-level similarity and dilutes a single
copied paragraph inside original text. Smaller chunks plus sentence-level alignment give
page- and timestamp-precise evidence. For real 5-page reports I would raise the size to about
150 to 200 tokens.
